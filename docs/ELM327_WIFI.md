# Wi-Fi ELM327: экспериментальный TCP-мост

Mac с USB–K-Line адаптером выступает сервером для программы, умеющей подключаться к Wi-Fi ELM327 по произвольному IP и TCP-порту. Отдельная точка доступа Wi-Fi не создаётся: используется существующая сеть. На самом Mac подключайтесь к 127.0.0.1:35000; с другого устройства — к LAN-IP Mac. Совместимость с конкретным диагностическим приложением пока не проверена.

## Проверка интерфейса без оборудования

```sh
cd /Users/alex/IdeaProjects/ELM327wifi
source .venv/bin/activate
python3 elm327_wifi.py
```

По умолчанию включён DEMO: ответы фиксированы и взяты из старого захвата. Это не актуальные измерения. Serial-порт не открывается. Для подключения с телефона в той же доверенной сети:

```sh
python3 elm327_wifi.py --host 0.0.0.0 --tcp-port 35000
```

В диагностической программе выберите Wi-Fi ELM327, задайте IP Mac и порт 35000. Не открывайте этот порт в интернет: аутентификации и шифрования нет. Поддерживается один клиент; бездействующее подключение закрывается через 60 секунд.

Пример текстового обмена, команды завершаются CR:

```text
ATE0
OK
>
ATSP5
OK
>
ATSH82B1F1
OK
>
ATH1
OK
>
2101
8B F1 B1 61 01 90 D2 BF 93 94 B0 FB 04 00 86
>
```

Поддержаны ATZ, ATWS, ATI, AT@1, ATD, ATE0/1, ATL0/1, ATS0/1, ATH0/1, ATSP5, ATDP, ATDPN, ATSH (физическая адресация, 3 байта), ATST. Баннер ELM327 v1.5 служит совместимости, но **не означает полной реализации ELM327**. Неизвестные команды возвращают `?`, отсутствующий ответ — `NO DATA`. Пустая команда повторяет последнюю. ATSP5 только выбирает формат; физическую fast-init последовательность не запускает. Автопоиск протокола, CAN, ATFI/ATSI, напряжение ATRV, автоматическое поддержание сессии не реализованы. Поэтому приложения с обязательной автоматической настройкой могут не подключиться.

## Реальная передача запросов

```sh
python3 elm327_wifi.py \
  --mode live --session-already-active \
  --port /dev/cu.usbserial-1110 --baudrate 10400 \
  --host 127.0.0.1 --tcp-port 35000
```

Требует `pyserial` из requirements.txt. Этот режим **активно отправляет запросы**, в отличие от kline_sniffer.py. Разрешены только известные запросы чтения: `21 01`, `18 00 80 00`, `1A 80`. Перед запросом удаляются старые входящие данные; ответ проверяется по длине, сумме, адресам и сервису; эхо запроса пропускается. Передача и ответы журналируются в терминале. При разрыве USB потребуется перезапуск.

**Самостоятельный запуск сессии блока ещё не реализован.** Флаг --session-already-active является явным выбором экспериментального режима, а не подтверждением связи. На блоке после включения питания могут быть только NO DATA. Не запускайте параллельно OpenDiag или sniffer на той же шине/порту: активные запросы могут конфликтовать. Для законченного автономного моста необходимо определить и реализовать инициализацию, поддержание сессии и протестировать это на оборудовании.

## Что даст готовая программа

Эмулятор заменяет интерфейс адаптера. Он не превращает параметры климата в стандартные OBD-II PID двигателя. Программа должна поддерживать пользовательские KWP-запросы, адрес блока B1 и формулы для ответа `61 01 ...`, либо готовый профиль этого блока. Расшифровка девяти байтов параметров пока не установлена. В demo поддержаны параметры и ошибки; идентификация не симулируется.

Тесты без оборудования:

```sh
python3 -m unittest discover -s tests -v
```
